# RPG 考試準備模式：知識遠征

日期：2026-09-12。狀態：第一版已實作，驗證與內容範圍見 docs/RPG-IMPLEMENTATION.md。

## 1. 產品定位與邊界

新增獨立的「RPG 冒險」入口，讓使用者透過探索地圖、解決委託、回合制戰鬥與營火複習準備考試。核心體驗是：每次學會一個概念，就能解決世界裡的一個問題。

以使用者提供的七張 SQL Quest 截圖作為互動與美術參考，改編為本站 AI 證照內容；不照搬 SQL 編輯器、產業題庫或角色名稱。這是產品設計提案，數字門檻是可調整的初始規則，並非學習成效研究結論。

硬性邊界：

- 原有模擬考、練習、知識學習、弱點診斷、錯題複習、統計與設定維持原來的路徑及行為。
- 首頁每張適用考試卡片增加一個入口；不替換現有按鈕、不將 RPG 設為預設模式。
- 共用題庫與題型呈現，但 RPG 任務、紀錄、複習排程與 XP 獨立儲存，不寫入原有考試成績或錯題本。
- 第一版只開放 AIF-C01；其他考試待章節配置、題庫審核與測試完成後才開放。
- 不以等級、裝備或地圖完成度表示真實考試通過率。

## 2. 現有基礎與可重用能力

以目前工作目錄的程式為準，舊規劃文件內的待辦不視為已上線功能。

| 目前可見的程式 | RPG 的用途 |
|---|---|
| `src/routes/index.tsx` 與現有五種學習路徑 | 只增加模式入口，維持既有流程 |
| `src/lib/exam-registry.ts` | 考試識別、領域配置、模擬考連結 |
| `src/lib/domains.ts` | 地區對應穩定的 domainNumber 與雙語名稱 |
| `src/lib/knowledge-chains.ts` | AIF-C01 的概念路線草稿，仍須人工整理成任務 |
| `src/lib/question-types.ts` | 單選、多選、排序、配對，以及提示、陷阱、解析、概念標籤 |
| `src/components/exam/QuestionView.tsx` | 共用答題呈現，RPG 父層管理戰鬥狀態 |
| `src/lib/questions.ts`、`src/server/api/questions.ts` | 題庫取得能力；RPG 加入獨立的適用題目篩選 |
| `src/lib/persistence.ts`、`src/lib/user-data.ts` | 參考既有保存方式；不能直接用原成績 API 儲存戰鬥結果 |
| `data/reviews/README.md` | 題目與當前 hash 相符的審核證據，不只看 reviewed 布林值 |

目前 `src/server/api/questions.ts` 將 `concepts` 與 `relatedQuestionIds` 回傳為空陣列，因此型別支援不代表已有可用概念關聯。MVP 地圖可依領域建立；技能節點必須先補獨立的人工整理 mapping，不能直接從 API 自動推導。現有身分是匿名 session cookie，未來跨裝置同步也必須另設復原／身分流程。

## 3. 世界觀與地圖

玩家是「知識修復師」，協助失去知識的城鎮恢復運作。每張證照是一片獨立大陸，每個考試領域是一個地區，概念群形成任務節點。

第一版 AIF-C01 大陸（依專案目前的領域設定命名，不宣稱已重新核對官方考綱）：

| 地區 | 考試領域 | 任務例子 | 區域 Boss |
|---|---|---|---|
| 起源草原 | D1：AI 與 ML 基礎 | 辨認分類與迴歸、選擇評估指標 | 過擬合幻獸 |
| 生成秘林 | D2：生成式 AI 基礎 | Token 與 Embedding、比較 RAG 與微調 | 幻覺之影 |
| 應用工坊 | D3：基礎模型的應用 | 服務選型、組合 RAG 流程、成本取捨 | 選型迷宮守衛 |
| 公平議院 | D4：負責任 AI | 找出偏差、選擇人類監督措施 | 偏差雙生像 |
| 治理堡壘 | D5：安全、合規與治理 | 權限、資料保護、稽核與治理 | 權限守門人 |

預設提供建議主線，但所有區域都可預覽與直接練習。劇情進度可有前後關係，學習內容不受 XP 或裝備限制；弱項玩家能直接前往需要的地區。

## 4. 一次 15–20 分鐘的遊玩

1. **回到營地，約 1 分鐘**：顯示上次進度、到期複習與今天的一個建議目標，可切換 5／15／30 分鐘任務。
2. **營火回想，約 3 分鐘**：先做 2–3 題到期題，提交後才展開解析。
3. **接取委託，約 2 分鐘**：NPC 用兩三句交代情境，例如「城鎮客服一直編造資訊，請找出修復方法」。保留正式技術名詞，不將考試題幹改寫成難懂的奇幻暗語。
4. **探索與戰鬥，約 8 分鐘**：完成 5 題，經過辨認概念、比較選項、情境應用；逐題顯示攻擊與解析。
5. **帶回戰利品，約 2 分鐘**：獲得 XP、地圖修復動畫，以及一張包含核心概念與常見陷阱的知識卡。
6. **安排下一步，約 1 分鐘**：列出尚未掌握的概念與下次回想時間，保存後可直接離開。

五分鐘模式縮為 3 題；沒有到期題就進入新任務，不製造多餘每日待辦。任務中途可保存，回來接續同一組題目及答案狀態。

## 6. 戰鬥、提示與獎勵規則

- 普通任務最多 5 題，敵人 100 HP；依題數等比例換算傷害。第一版每份 3 題，不用未審核內容湊滿題數。
- 任務結束答對至少 80% 視為本次勝利；不足則顯示「撤回營地整備」，保留已獲得的知識卡與紀錄，可立即再挑戰。
- 玩家以 5 格護盾表示本次失誤，答錯減一格；護盾不跨任務消耗、不限制學習、不需要等待恢復，也沒有付費補充。
- 單選是選擇技能；多選是組合技能；排序是修復流程；配對是連接符文。題型仍用正式說明，並沿用各題型的完整正確判定，不以部分分數冒充答對。
- 普通任務可用提示，提示後答對仍能推進故事，但標為「輔助完成」。不計入獨立掌握證據。
- 結算保留第一次提交結果；看完答案後修正能練習，但不能覆寫首次錯答。新一次挑戰另建 attempt。
- 第一版獎勵：首次無提示答對該題 +10 XP；使用提示後首次答對 +5 XP；到期且無提示複習答對 +5 XP；首次完成任務 +20 XP。一次答題只取一種答題 XP，任務獎勵另計。
- 同一題目版本立即重刷不增加 XP；到期複習每個排程事件最多給一次獎勵。重新整理或重送提交不重複領獎。
- 升級門檻暫定每 100 XP 一級。等級解鎖稱號與外觀，不提升答題傷害、不移除選項、不影響分數。
- 連續天數只供自我記錄，中斷不扣 XP、不失去裝備。

## 7. 學習掌握、複習與考前檢查

將「劇情完成」與「概念掌握」拆成兩個欄位。任務勝利能修復地圖；技能掌握需要額外證據。

### 概念狀態

- **未探索**：尚無作答紀錄。
- **學習中**：有嘗試，或僅在提示後答對。
- **待回想**：曾獨立答對，等待跨日檢查；或有錯題需要補強。
- **已掌握**：同一概念至少 3 道不同題目曾無提示答對，且其中至少一次是在另一日、距先前成功至少 24 小時的回想。
- **需要補強**：已掌握後又答錯，保留歷史證據並安排複習；XP 不倒扣。

題庫不足 3 道可用題時顯示「證據不足」，不靠重刷一題變成已掌握。語言切換不能將翻譯版本當新題；正式實作前建立穩定的題目家族識別。

### 營火排程

初始規則採連續成功後間隔 1／3／7／14／30 天。無提示答對前進一階；錯答或用提示退回第一階，安排隔日再測，當次另給即時解析與可選補練。時間儲存為 UTC，畫面依使用者當地日期顯示；待辦積欠不懲罰。

到期複習優先，接著是近期錯答概念，再依領域不足程度與尚未探索的內容選題。同次任務不重複抽同一題；題庫不足就縮短任務並說明，不能補入其他考試的題目。

### Boss 與考前檢查

第二階段領域 Boss 使用 10 題、跨領域試煉使用 15 題；均無提示、結束後統一公布答案，優先使用未見或較久未做的題。題目不足時不給完整試煉徽章。

遊戲中的 80% 通關線是內部練習規則。考前面板只顯示領域覆蓋、無提示正確率、最近作答日期、題數與未見題表現；不估算通過機率。提供連結前往既有模擬考，原本的計時、交卷與統計流程維持不變。

## 8. 考點與遊戲情境

依使用者補充，SQL Quest 的產業／職務專題僅是範例，不納入本專案。RPG 使用既有考試題庫，不另加金融、電商、製造或 DA／DS／DE 支線。

NPC 的短對話負責交代冒險目標；正式題幹保留原需求、限制與技術名詞。應用情境由原題考點決定，基礎辨識題不硬套故事。第一版不加入即時 AI 產題或程式執行環境。

## 9. 視覺與操作

延續參考圖的像素地圖、NPC、細框面板、金色重點與短對話；採「可讀的考試介面＋像素場景」組合，題幹與解析使用清楚的正文字體，像素字只用於少量裝飾。

- 桌面：左側 RPG 導覽、中間地圖／題目、右側任務資訊；戰鬥時以題目區優先。
- 手機：單欄題目、可收合敵人畫面，任務／地圖／營火以精簡導覽切換。
- 所有區域都可點選與鍵盤操作，地圖另提供等價清單；移動角色不是接題的必要操作。
- 減少動態效果設定下跳過攻擊動畫；不自動播放音效、不用顏色作為唯一結果訊號。
- RPG 容器局部覆寫 CSS tokens；離開後恢復原站主題，不改全域色票含義。
- 使用既有 shadcn／Radix 元件、專案圖示與 zh-TW／en i18n；專案目前禁止漸層，因此以純色像素圖與面板重現氛圍。

## 10. 技術切分與資料隔離

原規劃路由如下。第一版實際採 `/rpg/$code?view=map|quests|camp|skills|battle&quest=<id>`，在獨立容器內切換並保留深連結；不改既有路由：

| 路徑 | 用途 |
|---|---|
| `/rpg/$code` | 地圖、繼續冒險、初始化或錯誤畫面 |
| `/rpg/$code/quests` | 委託手冊 |
| `/rpg/$code/quest/$questId` | 答題戰鬥與結算 |
| `/rpg/$code/camp` | 營火複習 |
| `/rpg/$code/skills` | 技能與學習證據 |
| `/rpg/$code/trials` | 第二階段試煉公會 |

程式放在 `src/components/rpg/`、`src/lib/rpg/`；任務與地區配置放在獨立內容檔，避免把遊戲邏輯加進現有練習 route。地圖配置採 examCode + domainNumber，概念與題目關聯由版本化 manifest 管理。

資料最小集合：

- `RpgSave`：schemaVersion、examCode、campaignVersion、XP、外觀、最近節點。
- `QuestRun`：runId、questId、題目 ID／hash／順序、目前題號、已提交答案、狀態、開始與完成時間。
- `Attempt`：attemptId、runId、questionId、questionHash、conceptIds、首次答案、正確與否、hintUsed、answeredAt。
- `ReviewItem`：題目家族與概念、階段、dueAt、最近成功與失敗紀錄。
- `RewardClaim`：唯一事件鍵、XP 與時間，確保重送只領一次。

MVP 儲存於獨立 localStorage key `aistudyhub:rpg:v1:<examCode>`；一次提交將作答、獎勵與進度合併寫入同一份存檔。多分頁用單寫入者鎖，其他分頁提示接管或唯讀，避免互相覆蓋。此階段不支援跨裝置同步，也不宣稱離線可載入新題。

在 RPG 營地提供獨立存檔匯出／匯入與重置，驗證版本、考試代碼與基本結構；不改既有 `UserData.version: 1` 格式。localStorage 不可用或空間不足時顯示未保存狀態並提供匯出，不能假裝保存成功。存檔僅供個人練習，不作競賽可信成績。

未來同步使用獨立 RPG API 與 D1 表，沿用 session 身分而不擴寫既有 result／wrongAnswer 負載。將 append-only attempt／reward 事件作為合併依據，伺服器以唯一鍵去重後重建進度。

共用 `QuestionView` 若需要新增 RPG 所需的 hook 或 callback，必須是選配且預設維持舊行為；先檢查現有介面可否直接組合，優先不改共用元件。

## 11. 題庫門檻與例外

- 正式任務只收錄有效審核紀錄、ID/hash 相符、答案格式合法且有必要解析的題目；RPG 自有的查詢／建置清單實作此條件，不改舊模式篩選規則。
- 未審核內容可用於開發 fixture，但不計成正式可玩的內容。
- 檢查每個領域的可用題數、概念覆蓋、各題型支援與語言配對；先決定真實可開放的任務，再畫地圖節點。
- 讀取失敗和題庫為空需有不同畫面；現有 loader 有錯誤轉空陣列行為，RPG 應使用能區分失敗原因的 adapter。
- 題目 hash 改變後保留舊紀錄供查看，撤除對新版本的掌握證據並重新排程；不要因題目更新倒扣 XP。
- 存檔指向被移除題目時，保留既有答案並明示換題；不把新題當成已答題。
- 切換考試或語言不混用進度；語言共用同一題目家族的學習證據，未有配對翻譯時標示缺少內容。
